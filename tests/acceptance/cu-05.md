# Acceptance Tests — CU-05: Reportar foco de infección

**Fase:** F7 · **SDD de referencia:** SDD2_FASE4B_UBISAFE.md §9.6  
**Prerrequisitos:**
- Firebase emuladores corriendo (`firebase emulators:start --project demo-ubisafe`)
- FastAPI corriendo (`uvicorn main:app --reload`)
- App instalada en dispositivo/emulador con `adb reverse` configurado
- Usuario comprador autenticado con GPS activo

---

## SC-01 — Flujo normal: animal muerto

**Precondición:** GPS disponible; usuario a < 4 km de la coordenada a reportar.

**Pasos:**
1. Abrir la app como comprador → pantalla de mapa.
2. Tocar el FAB "+" → aparece SpeedDial con dos opciones.
3. Tocar "Foco de infección".
4. En el formulario, seleccionar tipo **"Animal muerto"**.
5. Verificar que se muestra la coordenada GPS actual como chip.
6. Tocar **Enviar**.

**Resultado esperado:**
- El form se cierra.
- Aparece un marcador de color rosado/negro en el mapa en la posición actual.
- El snippet del marcador dice "Animal muerto · Pendiente".
- En Firestore Emulator UI → colección `community_reports` → el documento tiene:
  - `threat_type: "animal_muerto"`
  - `status: "pending_validation"`
  - `radius_meters: 15`
  - `confirm_count: 0`, `dismiss_count: 0`
  - `is_duplicate: false`
  - `expires_at` ≈ now + 24h

## SC-02 — Flujo normal: zona sucia

**Precondición:** Igual a SC-01.

**Pasos:**
1. Tocar FAB "+" → "Foco de infección".
2. Seleccionar tipo **"Zona sucia"**.
3. Tocar **Enviar**.

**Resultado esperado:**
- Marcador de color naranja/café en el mapa.
- Snippet dice "Zona sucia · Pendiente".
- Firestore: `threat_type: "zona_sucia"`, `status: "pending_validation"`.

---

## SC-03 — Reporte fuera de rango (> 4 km)

**Precondición:** La API tiene `last_location` del usuario almacenada a > 4 km del GPS actual (simular enviando manualmente un PATCH `/auth/profile` con `last_location` lejana, o modificar el perfil en Firestore Emulator).

**Pasos:**
1. Tocar FAB "+" → "Foco de infección".
2. Seleccionar cualquier tipo → Enviar.

**Resultado esperado:**
- El formulario muestra un mensaje de error: "Tu ubicación está fuera del rango permitido (4 km)."
- No se crea ningún documento en `community_reports`.
- HTTP 400 con `detail: "location_out_of_range"` en logs de FastAPI.

---

## SC-04 — Duplicado agrupado (Cloud Function)

**Precondición:** Existe un reporte canónico activo con `threat_type: "animal_muerto"` a < 100 m del GPS actual.

**Pasos:**
1. Crear el reporte canónico manualmente en Firestore Emulator (o via SC-01 en un paso previo).
2. Tocar FAB "+" → "Foco de infección" → "Animal muerto" → Enviar.

**Resultado esperado:**
- El nuevo reporte se crea con `is_duplicate: true` y `canonical_report_id: <id-del-canónico>`.
- El nuevo marcador **no aparece** en el mapa (la lógica filtra `is_duplicate: true`).
- El marcador canónico permanece visible.
- En Firestore Emulator se confirma el campo `is_duplicate: true` en el segundo documento.

> **Nota:** El marcado como duplicado lo realiza la Cloud Function `aggregateDuplicateReports` asincrónicamente tras el `onCreate`. Puede tardar ~1-2 s en emulador.

---

## SC-05 — GPS no disponible

**Precondición:** Permisos de ubicación denegados o GPS desactivado.

**Pasos:**
1. Revocar permisos de ubicación a la app (Ajustes → Aplicaciones → UbiSafe → Permisos → Ubicación → Denegar).
2. Volver a la app → mapa.
3. Intentar tocar el FAB "+".

**Resultado esperado:**
- Se muestra el widget `GpsRequiredEmptyState` como bottom sheet (o el FAB no responde con SpeedDial y muestra el estado vacío).
- No se abre el formulario de reporte.

---

## SC-06 — Fallo de red con reintento

**Precondición:** GPS disponible; `adb reverse tcp:8000 tcp:8000` configurado.

**Pasos:**
1. Desactivar la conexión de red del dispositivo (modo avión) **después** de abrir el formulario.
2. Seleccionar tipo y tocar **Enviar**.
3. Esperar 2 s → el módulo reintenta (hasta 3 veces: 2 s, 4 s, 8 s).
4. Reactivar red durante el tercer reintento.

**Resultado esperado:**
- El reporte se envía exitosamente en el reintento que tiene red disponible.
- Aparece marcador en el mapa.
- Los logs de uvicorn muestran la petición `POST /community-reports` con `201`.
